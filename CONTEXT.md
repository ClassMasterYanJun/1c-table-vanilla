# Контекст проекта: дирижёр процессов и таблица маркировки для 1С

## Статус и назначение

Проект предоставляет автономную HTML-страницу для отображения и редактирования
данных 1С о номенклатуре, остатках кодов маркировки (КМ), данных для эмиссии,
остатках ВСД и связанных задачах. В эту же страницу встроен скрытый дирижёр,
который координирует фоновые процессы через 1С.

**Актуальная рабочая страница:** `1c-table-vanilla.html`.

Она рассчитана на запуск в WebView 1С или HTML-поле формы, не требует сети и
не использует внешние библиотеки. Все интеграционные точки доступны через
глобальный объект `window`.

## Файлы

| Файл | Назначение и статус |
|---|---|
| `1c-table-vanilla.html` | Единственная рабочая страница для формы 1С: видимая таблица и встроенный скрытый дирижёр. Чистые HTML, CSS и JavaScript; все изменения интерфейса вносятся сюда. |
| `1c-table-api.txt` | Подробный контракт интеграции с 1С и примеры вызовов. При изменении публичного API его необходимо обновлять вместе с HTML. |
| `1c-conductor.html` | Автономный справочный вариант дирижёра. Для формы 1С не загружается: его логика встроена в `1c-table-vanilla.html`. |
| `1c-conductor-api.txt` | Полный контракт встроенного дирижёра с 1С. |
| `1c-background-tasks.html` | Устаревший узкий прототип контроллера: хранит только список идентификаторов заданий. Для новых процессов использовать встроенный дирижёр. |
| `1c-background-tasks-api.txt` | Контракт устаревшего прототипа контроллера. |
| `1c-table-complete.html` | Предыдущая самостоятельная версия на Tabulator. Содержит другую модель интерфейса и диагностику; не является источником поведения для `1c-table-vanilla.html`. |
| `CONTEXT.md` | Этот актуальный технический контекст. |

### Важное различие версий

`1c-table-complete.html` содержит встроенный Tabulator и старую логику.
Он сохранён как исторический/сравнительный файл. Не следует переносить из него
API, стили или предположения о поведении в `1c-table-vanilla.html` без отдельной
проверки: актуальная страница реализована без Tabulator.

## Программа-дирижёр: целевая архитектура

### Назначение

Программа-дирижёр встроена в `1c-table-vanilla.html` как скрытая кнопка и
локальный JavaScript-код, не предназначенный для отображения пользователю.
Она является единой точкой координации процессов, а не только опрашивает
фоновые задания.

Её ответственность:

1. хранить актуальное состояние контролируемых процессов и идентификаторы
   фоновых заданий;
2. по расписанию инициировать один контролируемый вызов в 1С через скрытую
   кнопку;
3. передавать 1С снимок состояния и очередь накопившихся команд;
4. принимать от 1С обновлённое состояние, результаты выполненных операций и
   команды для рабочих страниц;
5. предотвращать дублирующиеся запросы, повторную отправку одной команды и
   параллельные циклы обработки;
6. вести локальные диагностические данные: время последнего запуска, последнего
   успешного ответа, последнюю ошибку и состояние выполняемого запроса.

Дирижёр **не должен** содержать прикладную бизнес-логику 1С, самостоятельно
работать с базой, определять результат фонового задания или подменять 1С как
источник истины. Он управляет последовательностью обмена; решения и запись
данных остаются на стороне 1С.

### Рекомендуемый цикл обработки

```text
дирижёр (таймер)
  -> скрытая кнопка
  -> 1С получает состояние и очередь команд
  -> 1С проверяет фоновые задания, переносит/собирает данные
  -> 1С передаёт дирижёру обновлённое состояние и подтверждения
  -> дирижёр фиксирует результат и ожидает следующий цикл
```

Таймер не должен запускать новый обмен, пока предыдущий не подтверждён 1С или
не истёк явно заданный тайм-аут. Это защищает от наложения проверок, если
фоновая обработка выполняется дольше интервала.

### Реализованное рабочее состояние

Минимально необходимая модель состояния:

```js
{
  tasks: [
    {
      taskId: "идентификатор-задания",
      type: "preparePrintForms",
      rowUuids: ["uuid-строки"],
      createdAt: "2026-09-09T00:00:00.000Z",
      status: "running",
      payload: {}
    }
  ],
  commandQueue: [
    { id: "уникальный-id", type: "syncTable", payload: {}, "createdAt": "2026-09-09T00:00:00.000Z" }
  ],
  processing: false,
  lastRunAt: "2026-09-08T03:00:00",
  lastSuccessAt: "2026-09-08T03:00:01",
  lastError: null
}
```

Поле `tasks` хранит связь фонового задания с конкретными строками основной
таблицы. Идентификаторы, задачи и команды являются сериализуемыми JSON-данными.
Объекты формы 1С, ссылки на элементы интерфейса, функции и другие внутренние
объекты платформы в состояние не передаются.

### Реализованный контракт с 1С

1. По таймеру (по умолчанию раз в 5000 мс) встроенный дирижёр всегда нажимает
   скрытую кнопку `#conductorTickBtn`, в том числе при отсутствии активных
   задач и команд.
2. Кнопка вызывает `window.processConductorIn1C(state)`, передавая копию
   состояния. В `state.tasks` находится список активных фоновых заданий с
   `taskId`, `type`, `status`, `rowUuids`, `createdAt` и `payload`; 1С проверяет
   их статусы по `taskId`, обрабатывает очередь и при необходимости обновляет
   ту же таблицу через её глобальные API.
3. Если обработчик 1С возвращает ответ синхронно, страница сразу применяет его.
   Для асинхронного сценария 1С должна позднее вызвать
   `window.applyConductorResponse(response)`.
4. При обновлении задачи через `taskUpdates` со статусом `completed` дирижёр
   устанавливает `printStatus: true` у строк из её `rowUuids` и удаляет задачу.
   `completedTaskIds` выполняет те же действия для совместимости. `failedTaskIds`
   помечает задачу ошибочной, но не меняет строки. Ответ также может подтверждать
   команды (`acknowledgedCommandIds`).
5. Пока `processing === true`, новый цикл не запускается. Если 1С не ответила
   за 60000 мс по умолчанию, дирижёр снимает блокировку и записывает ошибку.
   Интервал и тайм-аут настраиваются методами `setConductorInterval()` и
   `setConductorTimeout()`; минимальное допустимое значение — 1000 мс.

Основные публичные методы:

| Метод | Назначение |
|---|---|
| `getConductorState()` / `setConductorState(state)` | Получить копию или восстановить всё состояние после перезагрузки HTML-поля. |
| `getActiveConductorTasks()` | Получить копии только активных фоновых заданий (`state.tasks`) для проверки их статусов в 1С. |
| `addConductorTask(task)` / `updateConductorTask(taskId, values)` / `removeConductorTask(taskId)` | Управление активными фоновыми заданиями. |
| `enqueueConductorCommand(command)` / `acknowledgeConductorCommands(ids)` | Добавление и подтверждение очереди команд. |
| `runConductorCycle(force)` | Немедленно запустить один цикл; с `force === true` допускается пустое состояние. |
| `applyConductorResponse(response)` | Принять асинхронный компактный ответ 1С и завершить цикл. |
| `startConductor()` / `stopConductor()` | Запустить или остановить таймер. |

Подробные форматы и примеры — в `1c-conductor-api.txt`.

## Граница HTML и 1С

### Базовое правило

Текущая форма загружает один файл `1c-table-vanilla.html`, поэтому таблица и
дирижёр работают в одном объекте `window` и 1С может применять дельты напрямую:

```js
window.updateRowByUuid(uuid, { printStatus: true });
```

Передача объекта формы 1С напрямую в HTML по-прежнему не является корректным
контрактом: он не сериализуется в JSON и привязывает страницу к внутреннему
устройству конкретной формы.

### Основной и надёжный способ: 1С как посредник

Это рекомендуемая архитектура для текущего проекта:

1. дирижёр вызывает ограниченный обработчик 1С через скрытую кнопку;
2. 1С получает JSON-снимок состояния дирижёра и выполняет проверку заданий,
   перенос или сбор данных;
3. 1С вызывает API этой же страницы, например `updateRowByUuid`,
   `setTableData` или `setPrintSettings`;
4. 1С возвращает дирижёру JSON-результат и подтверждения обработанных команд.

Так 1С остаётся источником бизнес-данных и транспортом обмена. Это не требует
сети, внешних библиотек или зависимости от внутреннего устройства WebView.

### Если снова появятся несколько HTML-полей

| Механизм | Когда применим | Почему не выбран основным |
|---|---|---|
| `window.postMessage()` | Страницы действительно находятся в одном окне через `iframe` или имеют ссылку друг на друга. | Для отдельных HTML-полей 1С обычно нет общей ссылки на окно; требуется отдельно подтвердить среду и origin. |
| `localStorage` + событие `storage` | Страницы имеют одинаковый origin и используют один профиль WebView. | В разных версиях и режимах WebView 1С доступность, origin и сохранность хранилища могут отличаться; событие не приходит в окно-источник. |
| `BroadcastChannel` | Современный браузер, общий origin. | Может отсутствовать в устаревшем WebView; не соответствует требованию максимальной совместимости. |
| Прямой доступ через `window.parent` / `window.frames` | Только если страницы специально встроены в один HTML-документ. | Текущие страницы запускаются независимо; такая связность усложнит форму и нарушит изоляцию. |

Использовать эти механизмы можно только после практической проверки в целевой
версии платформы 1С. Они не заменяют контракт 1С-посредника.

### Границы API

Обмен должен быть событийным и явным. Вместо передачи формы или произвольного
выполнения кода следует передавать JSON-команды фиксированных типов, например:

```js
{ "id": "cmd-001", "type": "refreshTable", "payload": {} }
{ "id": "cmd-002", "type": "setPrintSettings", "payload": { "markingDate": "08.09.2026" } }
{ "id": "cmd-003", "type": "checkBackgroundTasks", "payload": { "taskIds": ["..."] } }
```

Каждая команда должна иметь уникальный `id`; 1С и дирижёр подтверждают её
обработку. Это позволяет безопасно повторять обмен после ошибки, не выполняя
одно действие дважды.

## Целевой поток обработки маркировки и печати

### Проблема, которую решает дирижёр

Основная форма 1С одновременно показывает таблицу, собирает большой объём
данных, запускает формирование печатных форм и ожидает результаты фоновых
заданий. При передаче полного объёма данных в HTML или обработке тяжёлой
логики в интерактивном сеансе форма зависает, и пользователь не может
продолжать работу.

Дирижёр не делает тяжёлые операции сам. Его задача — отделить короткие
интерактивные вызовы от асинхронных операций 1С и обеспечить передачу только
необходимых изменений в основную таблицу.

### Последовательность процесса

```text
1. Открытие формы
   1С собирает компактный снимок строк, нужных для отображения,
   и передаёт его в 1c-table-vanilla.html через setTableData().

2. Подготовка к печати
   Пользователь или прикладная логика 1С отбирает строки с готовыми КМ.
   1С создаёт фоновое задание формирования печатных форм.
   В дирижёр передаются идентификатор задания и идентификаторы затронутых строк.

3. Фоновое выполнение
   Формирование табличных документов происходит вне интерактивного обработчика
   формы 1С. Пользователь может продолжать работу с таблицей.

4. Проверка завершения
   Дирижёр по интервалу вызывает 1С через скрытую кнопку. 1С проверяет только
   задания, идентификаторы которых передал дирижёр, а не выполняет полный обход
   всех данных.

5. Разбор результата
   После завершения задания 1С переносит сформированные печатные формы в свои
   прикладные таблицы/хранилища. Затем передаёт дирижёру обновление задачи со
   статусом `completed`. Дирижёр сам установит `printStatus: true` у связанных
   строк из `rowUuids` и удалит завершённую задачу. При ошибке 1С передаёт
   статус `failed`, не меняя строки.

6. Обновление интерфейса
   При обработке `completed` дирижёр обновляет затронутые строки через
   `updateRowByUuid()` и устанавливает `printStatus: true`. Это сразу отображает
   иконку принтера и обновляет раздел задач печати.

7. Фоновое обновление данных
   Изменения, не связанные с одним заданием, собираются 1С отдельно и передаются
   в таблицу пакетно: либо как дельта изменившихся строк, либо как полный снимок
   только по явному запросу пользователя/при открытии формы.
```

### Контракт фонового задания

Для каждого запущенного формирования дирижёру нужен не только идентификатор
фонового задания, но и связь с затронутыми строками таблицы:

```json
{
  "taskId": "идентификатор-фонового-задания",
  "type": "preparePrintForms",
  "rowUuids": [
    "uuid-строки-1",
    "uuid-строки-2"
  ],
  "createdAt": "2026-09-08T04:00:00",
  "status": "running"
}
```

После завершения 1С должна передать результат с явным итоговым состоянием, а
не заставлять HTML угадывать его по отсутствию задания. Для связанной задачи
достаточно её идентификатора и статуса: строки определяются из `rowUuids`,
сохранённых при добавлении задачи.

```json
{
  "taskUpdates": [
    {
      "taskId": "идентификатор-фонового-задания",
      "status": "completed"
    }
  ]
}
```

При ошибке `status` должен быть `failed`, `printStatus` не должен выставляться
в `true`, а текст/код ошибки должен оставаться на стороне 1С и при необходимости
передаваться отдельным полем строки или сообщением интерфейса.

### Правило дельта-обмена

При `status: "completed"` дирижёр сам вызывает `updateRowByUuid()` для каждой
строки задачи. Для других точечных изменений уже открытой таблицы следует
использовать:

```js
window.updateRowByUuid(uuid, {
  printStatus: true
});
```

Этот метод уже принимает объект или JSON-строку, сортирует данные, перерисовывает
таблицу, обновляет задачи и сохраняет пользовательские правки эмиссии. Он
предпочтительнее `setTableData()` для изменения статуса нескольких конкретных
строк. При нескольких изменениях 1С должна по возможности передавать их одним
пакетом через будущий массовый API, а не выполнять большой полный обмен для
каждой строки.

`setTableData()` остаётся для начальной загрузки и редких полных обновлений.
Нельзя вызывать его через короткий интервал с большим полным массивом, если
достаточно нескольких изменённых строк.

### Распределение ответственности

| Слой | Ответственность |
|---|---|
| Основная HTML-таблица | Визуально отображает текущие данные, принимает локальные правки и показывает состояния `emissionStatus`, `printStatus`, `printed`. Не формирует печатные формы. |
| Дирижёр | Хранит состояние процессов, очередь заданий и команды; запускает короткий регулярный обмен; не собирает большой набор бизнес-данных. |
| 1С, интерактивная форма | Передаёт начальные данные, запускает фоновую операцию и применяет небольшие результаты к HTML-страницам. Не ожидает завершения длительного фонового задания. |
| 1С, фоновое задание | Формирует печатные формы и возвращает результат. Здесь находится тяжёлая работа. |
| 1С, серверный обработчик завершения/проверки | Разносит результаты по прикладным таблицам, формирует дельту статусов и передаёт её дирижёру/таблице. |

### Производительность: обязательные ограничения

1. Не передавать в HTML табличные документы, двоичные данные, макеты или
   полный состав данных обработки. В HTML нужны только поля для отображения и
   идентификаторы.
2. Не опрашивать весь реестр фоновых заданий на каждом тике. Проверять только
   известные активные `taskId` дирижёра.
3. Не выполнять формирование печатных форм в обработчике нажатия кнопки формы;
   он должен лишь создать фоновое задание и быстро вернуть управление.
4. Не обновлять полную таблицу при завершении одного задания. Передавать
   изменения строк по `uuid` и отдельно удалять завершённый `taskId`.
5. Объединять частые изменения в один небольшой пакет. Период проверки выбирать
   по реальной длительности заданий; преждевременный интервал 1–2 секунды создаёт
   лишнюю нагрузку и не делает результат быстрее.
6. В интерактивной форме не ожидать синхронно завершения фонового задания.
   Тайм-аут и повторные проверки контролирует дирижёр совместно с 1С.

## Технические ограничения и устройство страницы

- Нет зависимостей: только нативный DOM API, ES5-совместимый JavaScript и CSS.
- Основной файл намеренно сжат в небольшое число длинных строк.
- `html` и `body` имеют `overflow: hidden`: сама страница не прокручивается.
- Основная область состоит из таблицы и правой панели задач. Прокручивается
  только `.table-wrap`; панель задач прокручивается независимо.
- Верхняя панель параметров печати и строка фильтров занимают по 42 px;
  рабочая область занимает оставшуюся высоту окна.
- Таблица использует `table-layout: fixed`. Заголовок фиксируется клонированием
  `colgroup` и `thead` при вертикальной прокрутке; в `pinHeader()` для копии
  синхронизируются ширины ячеек первой строки данных. Для совместимости с
  WebView 1С копия шапки позиционируется абсолютно внутри области прокрутки:
  её `top` равен `scrollTop`, а горизонтальное смещение выполняется браузером
  вместе с таблицей, без `position: fixed`, `transform` и расчёта координат окна.
  Клон получает класс `table-header-clone` с теми же критичными правилами
  геометрии, что и основная таблица, но без дублирования `id="dataTable"`.
- Правая панель «Задачи» изначально имеет ширину 260 px, минимальную ширину
  180 px и меняется перетаскиванием разделителя `#tasksResizer`.
- Демо-массив `sampleData` сейчас пуст. Данные должны поступить от 1С или через
  `window.setTableData()`.

## Интерфейс страницы

### Верхняя панель печати

Отображает:

- дату маркировки (только чтение, передаётся 1С в `markingDate`);
- список шаблонов этикеток;
- флаг «Нумеровать при печати»;
- флаг «Сразу на принтер».

Страница не задаёт начальных значений печати. До передачи настроек из 1С дата
и список шаблонов пусты, флажки сняты. Параметры задаются через
`window.setPrintSettings()` и читаются через `window.getPrintSettings()`.

### Фильтры и поиск

Фильтры применяются только к отображению таблицы, но не меняют `window.tableData`
и не влияют на состав задач:

- «Готовые к нанесению»: `emissionStatus === true` / `false`;
- «Вид продукции»: весовая или штучная;
- поле поиска расположено над панелью задач, повторяет её ширину при изменении
  разделителя и фильтрует по подстроке `nomenclature` без учёта регистра;
  подсказка «Поиск» отображается внутри пустого поля и скрывается при вводе;
- кнопка «Отменить» очищает поиск.

### Основная таблица

Колонки:

1. `rowNumber` — №;
2. `nomenclature` — Номенклатура;
3. `unit` — Ед. изм.;
4. `marksCount` и индикатор `emissionStatus` — Остаток КМ / Эмиссия: сначала отображается количество марок, затем индикатор;
5. индикатор `printStatus` — Остаток КМ / Печать;
6. `emissionWeight` — Данные для эмиссии КМ / Вес (кг);
7. `emissionQuantity` — Данные для эмиссии КМ / Количество;
8. `vsdBalance` — Остаток ВСД.

Строки всегда сортируются по `nomenclature` в алфавитном порядке без учёта
регистра после загрузки, прямого обновления, ручного обновления и синхронизации.

#### Ширина «Ед. изм.»

Третий столбец имеет класс `col-unit`. При каждом `render()` функция
`updateUnitColumnWidth()` измеряет через Canvas ширину заголовка «Ед. изм.» и
максимального значения `unit` среди **всех** строк. К результату добавляются
горизонтальные отступы ячейки, и ширина устанавливается в пикселях. Поэтому
фильтрация не меняет геометрию столбца, а новые данные 1С корректно её
пересчитывают до создания закреплённой шапки.

### Выделение, навигация и редактирование

- Одиночный клик выделяет строку. Выделение хранится по `id` и восстанавливается
  после перерисовки, сортировки и периодической синхронизации, пока строка
  остаётся в данных. Если строка скрыта фильтром, её выбор сохраняется и снова
  отображается после снятия фильтра.
- Стрелки вверх/вниз перемещают выделение. Для штучного товара переход к строке
  открывает редактирование поля веса.
- Поля `emissionWeight` и `emissionQuantity` редактируются двойным кликом.
- `Enter` применяет изменение; `Esc` отменяет ввод; потеря фокуса также
  завершает редактирование.

#### Штучный товар

Если `isWeighted === false`:

- изменение количества пересчитывает вес: `quantity * weightPerUnit`;
- изменение веса пересчитывает количество: `ceil(weight / weightPerUnit)` при
  положительном `weightPerUnit`;
- вес округляется до трёх знаков после запятой;
- отрицательные введённые значения заменяются на `0`.

#### Весовой товар

Если товар весовой, попытка редактирования открывает модальное окно вместо
встроенного поля. В окне вводятся общий и средний вес; результат рассчитывается
как `ceil(общий вес / средний вес)`. При среднем весе `0` показано сообщение
об ошибке. Подтверждение сохраняет оба значения, отмена восстанавливает
предыдущие значения.

#### Определение весового товара

`window.isWeightedProduct(row)` возвращает:

1. `row.isWeighted`, если это Boolean;
2. иначе `true` только для `unit`: `кг`, `килограмм`, `kilogram`
   (без учёта регистра и внешних пробелов).

## Статусы КМ и печати

- Истинный `emissionStatus` показывает индикатор Data Matrix.
- Истинный `printStatus` показывает иконку принтера.
- Если `emissionStatus` истинный, а `printStatus` ложный, в столбце «Печать»
  показывается индикатор подготовки к печати.
- Клик по иконке принтера выделяет строку и вызывает необязательный обратный
  вызов `window.printRow(row)`, если 1С его предоставила.
- Поле `printed` не управляет иконкой принтера: оно используется только для
  задачи ввода отчёта о нанесении.

Для отображения статусов допускаются Boolean `true`/`false` и строки
`"true"`/`"false"`; для стабильной интеграции следует передавать Boolean.

## Панель «Задачи»

Панель независима от таблицы и включает четыре раздела. Состав задач
пересчитывается при каждом `render()`, то есть при загрузке/синхронизации,
изменении данных, фильтрах, редактировании и прямых изменениях отслеживаемого
массива.

| Раздел | Условие попадания строки | Отображаемое значение | Метод / результат |
|---|---|---|---|
| К эмиссии марок | `emissionQuantity > 0` | Количество | `executeEmissionTasks()` / `window.emissionTaskRows` |
| Напечатать КМ по очереди | `printStatus === true` | `marksCount` (КМ) | `executePrintTasks()` / `window.printTaskRows` |
| Заказать ВСД | `vsdBalance < emissionWeight` | `vsdShortageKg` (кг) | `executeVsdTasks()` / `window.vsdTaskRows` |
| Ввести отчет о нанесении | `printed === true && printStatus === false` | Наименование с флажком | `executeReportTasks()` / `window.reportTaskRows` |

Для задачи ВСД к копии строки добавляется `vsdShortageKg`:

```text
round3(emissionWeight - vsdBalance)
```

Кнопка «Выполнить» каждого раздела отключается, если в его списке нет строк,
и активируется автоматически, как только появляется хотя бы одна строка.
В разделе отчёта кнопка активна при наличии задач; в его итоговый массив входят
только строки, отмеченные пользователем флажками. Поэтому нажатие при невыбранных
флажках законно возвращает пустой массив.

Нажатие кнопки не выполняет внешнее действие самостоятельно: оно формирует и
возвращает соответствующий массив, который 1С затем читает из `window`.

## Формат строки данных

Рекомендуемый контракт:

```json
{
  "id": 101,
  "uuid": "2a38c4bc-df44-4ce6-b5ce-cf6f88df0e12",
  "rowNumber": 1,
  "nomenclature": "Колбаса вареная",
  "isWeighted": false,
  "unit": "шт",
  "weightPerUnit": 0.45,
  "emissionStatus": true,
  "marksCount": 150,
  "printStatus": false,
  "printed": true,
  "emissionWeight": 45,
  "emissionQuantity": 100,
  "vsdBalance": 20
}
```

| Поле | Тип | Назначение |
|---|---|---|
| `id` | number или string | Идентификатор строки; используется для DOM-строки и сохранения локальных правок. |
| `uuid` | string | Устойчивый идентификатор для `updateRowByUuid()`. |
| `rowNumber` | number | Отображаемый номер строки. |
| `nomenclature` | string | Наименование; определяет сортировку и поиск. |
| `isWeighted` | boolean | Признак весового товара. При отсутствии работает резервная проверка `unit`. |
| `unit` | string | Единица измерения; определяет ширину столбца и резервно тип товара. |
| `weightPerUnit` | number | Средний вес единицы для расчётов. |
| `emissionStatus` | boolean | Наличие/готовность КМ и управление визуальным индикатором. |
| `marksCount` | number | Количество КМ. |
| `printStatus` | boolean | Готовность к печати и задача печати. |
| `printed` | boolean | Признак уже напечатанной позиции для отчёта о нанесении. |
| `emissionWeight` | number | Вес для эмиссии КМ. |
| `emissionQuantity` | number | Количество для эмиссии КМ. |
| `vsdBalance` | number | Остаток ВСД. |

При загрузке `printed` нормализуется строго: только Boolean `true` остаётся
`true`, остальные значения становятся `false`. Следовательно, 1С должна
передавать это поле именно Boolean, а не строкой.

## Интеграция с 1С

Полные примеры находятся в `1c-table-api.txt`. Ниже перечислены актуальные
интерфейсы и их смысл.

### Загрузка и получение данных

| Интерфейс | Назначение |
|---|---|
| `window.setTableData(data)` | Полностью заменяет данные. Принимает `Array<Object>` или JSON-строку с массивом. Неверный ввод игнорируется. |
| `window.tableData` | Свойство: чтение возвращает рабочий массив, присваивание аналогично `setTableData()`. |
| `window.rows` | Алиас `window.tableData`. |
| `window.GetDataTo1C()` | Возвращает массив копий всех текущих строк. |
| `window.refreshTable()` | Сортирует и перерисовывает данные после прямой правки. |
| `window.checkTableDataChanges()` | Немедленно проверяет прямые правки; возвращает `true`, если интерфейс обновлён. |
| `window.updateRowByUuid(uuid, values)` | Обновляет строку по `uuid`; `values` — объект или JSON-строка объекта. Поля `id` и `uuid` игнорируются. Возвращает копию строки или `null`. |

`updateRowByUuid()` сохраняет локальную правку, если изменены `emissionWeight`
или `emissionQuantity`, затем сортирует и полностью обновляет интерфейс.

### Синхронизация

1. 1С может определить `window.getDataFrom1C()`, возвращающую массив строк или
   JSON-строку с массивом.
2. `window.SetDataFrom1C()` вызывает этот метод, проверяет формат, объединяет
   новые строки с локальными правками из `window.editedRows`, сортирует и
   перерисовывает страницу.
3. Полный вызов `SetDataFrom1C()` выполняется только явно: при открытии формы,
   по действию пользователя или по отдельной команде 1С. Таймер дирижёра не
   вызывает его автоматически.

Если `getDataFrom1C` не определена, синхронизация ничего не меняет.

### Локальные правки

`window.editedRows` имеет вид:

```js
{
  "101": {
    emissionWeight: 12.5,
    emissionQuantity: 28
  }
}
```

Это защита пользовательских правок полей эмиссии от перезаписи очередной
синхронизацией 1С. При `SetDataFrom1C()` сохранённые значения накладываются на
строку с тем же `id`.

### Прямые изменения массива

Код раз в 500 мс сериализует текущие `rows` и сравнивает сигнатуру. Поэтому
изменения отдельных объектов в `window.tableData` обнаруживаются без явного
вызова `refreshTable()` не позднее чем через 500 мс. Синхронное обновление
возможно через `window.checkTableDataChanges()`.

### Настройки печати

| Интерфейс | Назначение |
|---|---|
| `window.setPrintSettings(settings)` | Устанавливает дату, шаблоны и флаги печати и обновляет верхнюю панель. Принимает объект или JSON-строку с объектом. |
| `window.getPrintSettings()` | Возвращает `markingDate`, `labelTemplate`, `numberLabels`, `sendToPrinter`. |
| `window.printSettings` | Текущий объект настроек. Для изменения предпочтителен `setPrintSettings()`, чтобы обновить DOM. |

Параметр `settings` может содержать `labelTemplates` (массив `{value, text}`),
`labelTemplate`, `numberLabels`, `sendToPrinter`. Все поля необязательны.

### Задачи и пользовательские действия

| Интерфейс | Назначение |
|---|---|
| `window.executeEmissionTasks()` | Формирует и возвращает `window.emissionTaskRows`. |
| `window.executePrintTasks()` | Формирует и возвращает `window.printTaskRows`. |
| `window.getReadyForPrintUuids()` | Возвращает массив объектов `{ uuid: "..." }` для строк с `emissionStatus === true` и `printStatus === false`; строки без UUID не включаются. |
| `window.getReadyForPrintTasks()` | Возвращает готовые к подготовке печати UUID с `hasActiveTask`, `taskId` и `taskStatus`; позволяет 1С не запускать повторное задание `preparePrintForms` по уже обрабатываемой строке. |
| `window.executeVsdTasks()` | Формирует и возвращает `window.vsdTaskRows`. |
| `window.executeReportTasks()` | Формирует и возвращает отмеченные `window.reportTaskRows`. |
| `window.editRow(id)` | Выделяет строку с указанным `id` и прокручивает таблицу к ней. |
| `window.printRow(row)` | Необязательный обратный вызов, который должна предоставить 1С для печати одной строки. |

### Вспомогательные интерфейсы модального окна

- `window.isWeightedProduct(row)`;
- `window.calculateModalResult()`;
- `window.confirmWeightModal()`;
- `window.closeWeightModal()`.

Они доступны глобально для работы страницы. Для стандартного обмена 1С обычно
нужны только `isWeightedProduct()` и методы из предыдущих разделов.

## Важные ограничения текущей реализации

1. Таблица и код не используют фреймворки: не добавлять Tabulator, jQuery,
   React или внешние CDN без отдельного архитектурного решения.
2. Функции `document.onmousemove`, `document.onmouseup` и `window.onresize`
   назначаются напрямую. Внешний код, который перезапишет их, может нарушить
   изменение ширины панели или синхронизацию закреплённого заголовка.
3. Закреплённая шапка рассчитывается при каждой перерисовке; изменения ширин
   колонок нужно выполнять до вызова `pinHeader()`.
4. `window.tableData` возвращает фактический массив, а не копию. Это позволяет
   менять объекты напрямую, но автоматически сортирует и перерисовывает таблицу
   при следующей проверке сигнатуры.
5. Кнопки задач отражают наличие задач, а не наличие флажков в задаче отчёта.
   Для передачи отчёта пользователь должен дополнительно отметить нужные строки.
6. Публичный контракт в `1c-table-api.txt` является источником примеров
   интеграции. При доработке данных или задач необходимо актуализировать и его,
   и данный контекст.

## Проверка после изменений

Для проверки синтаксиса встроенного JavaScript можно выполнить из каталога
проекта:

```cmd
node -e "const fs=require('fs');const html=fs.readFileSync('1c-table-vanilla.html','utf8');const parts=html.split('<script>').slice(1).map(function(part){return part.split('</script>')[0]});if(parts.length!==3)throw new Error('Ожидалось 3 встроенных сценария');parts.forEach(function(script){new Function(script)});console.log('Синтаксис встроенных сценариев корректен');"
```

Минимальная ручная проверка в WebView:

1. передать тестовые данные с весовым и штучным товаром;
2. убедиться в сортировке, фильтрах, поиске и закреплении шапки при прокрутке;
3. проверить пересчёт веса/количества и модальное окно;
4. проверить включение/отключение кнопок задач при изменении статусов;
5. проверить вызов `printRow`, `GetDataTo1C`, `updateRowByUuid` и ручной
   `SetDataFrom1C()`;
6. добавить задание дирижёра, проверить единственный вызов
   `processConductorIn1C(state)`, синхронный или асинхронный ответ через
   `applyConductorResponse()`, установку `printStatus: true` у строк из
   `rowUuids` при статусе `completed`, удаление задачи и отсутствие
   параллельного цикла.
